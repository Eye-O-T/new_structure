18:56:37~19:01:28 KST, 약 10초 간격 30표본을 수집했다. 전체 5분 동안 사람의 유무와 Desktop 화면 배치는 확인하지 못했다. 아래 좌표 나이와 stale은 전처리 상태 API의 값이며 좌표 조회 API의 1초 표본이나 화면 지연이 아니다. 원본은 백업 폴더의 `baseline.jsonl`이다.

양쪽 카메라 녹화 디렉터리에서 최근 파일 갱신을 확인했다. 실제 영상 재생과 신규 세그먼트의 연속성은 검증하지 않았다.

## 남은 작업

1. 사람을 양쪽 카메라에 등장시킬 수 있는 상태와 Desktop 접근을 확보하고, 현재 설정·이미지·송출·녹화 및 복구 자료를 재확인한다. 기준 측정은 전환 직전 동일 조건으로 다시 수행한다.
2. 계획서에 따라 분석을 정상 중지하고 전처리만 고정 이미지로 재생성한다. 두 탐지 워커와 OSNet의 GPU 실행, 실제 사람의 신선한 좌표와 화면 bbox를 확인한다.
3. 분석을 GPU로 전환하고 카메라별 신규 이벤트와 분석 완료, 동시 부하 및 15분 안정성을 검증한다. 완료 기준을 충족하지 못하면 계획서의 실패 분기와 CPU 복구 절차를 따른다.

## 영상 연결 오류 후속 조치

19:08경 카메라 영상 연결 오류와 External의 Data 조회 시간 초과를 확인했다. 전처리 중지 후 두 영상이 표시됐고, CPU 전처리를 다시 시작했을 때 API 503이 재발해 영상 복구를 우선하여 전처리를 다시 중지했다. 카메라 조회마다 녹화 디렉터리를 오래된 순서로 재귀 탐색하는 경로를 확인했으며, 전처리 중지 상태에서도 해당 검사에 cam-001 약 3.07초, local-camera 약 1.18초가 걸렸다.

최근 이름의 디렉터리와 파일부터 검사하고 필요한 경우 나머지도 검사하도록 수정했다. 실제 녹화 파일을 읽기 전용으로 연결한 수정 이미지에서 각각 약 0.060초와 0.038초가 걸렸으며 녹화 제어 회귀 검사 3개가 통과했다. 사용자 승인 후 19:50:09~19:50:11에 Data 컨테이너를 수정 이미지 `sha256:5774d43f3097ef9a53421ab287b2e064f1a64631fea21a2f8aee2862a475b802`로 교체했다. 이후 초기 녹화 대조를 거쳐 healthy가 되었고 카메라별 내부 조회 3회는 모두 200, 약 0.05~0.06초였다. 기존 이미지는 `ai-cctv-data:rollback-recording-scan-20261115`에 보존했다.

Data 교체 전 19:49경 전체 녹화 중지 요청이 진행 중이었고, 교체 후 두 MediaMTX 경로는 송출원이 없는 상태였다. 전처리는 중지 상태이며 실제 송출·화면 및 GPU 전환 검증은 두 카메라를 다시 시작한 뒤 필요하다. 수정 이미지의 운영 환경에서 장시간 안정성은 아직 검증하지 않았다.
